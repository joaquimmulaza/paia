# F0 · Fundação — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** criar um repositório que arranca e verifica tudo com `npm run verify`, com tokens do Cartaz, os primeiros componentes shadcn/ui restilizados, a base de dados de perfis com RLS testada e os ecrãs Entrar, Criar conta e Perfil a funcionar contra o Supabase local.

**Arquitetura:** aplicação estática React + Vite. O Supabase local (Docker) serve a autenticação e o Postgres. O perfil é criado por um trigger a partir dos metadados do registo. As permissões vivem nas RLS e nos `grant`. O frontend só usa a chave pública.

**Tecnologias:**
- **Aplicação:** Node 24 (instalado), React 18.3, Vite 6, TypeScript 5 (strict), React Router 6, TanStack Query 5, react-hook-form 7 + zod 3 + @hookform/resolvers, @supabase/supabase-js 2.
- **Interface:** Tailwind CSS 4, shadcn/ui (Radix), class-variance-authority, tailwind-merge, clsx, lucide-react, sonner.
- **Testes e qualidade:** Vitest + @testing-library/react + jsdom, Playwright + @axe-core/playwright, supabase CLI (dependência de desenvolvimento), pgTAP, ESLint 9 (com jsx-a11y) e Prettier.

**Especificação:** `docs/superpowers/specs/2026-11-25-paia-desenho-tecnico.md` (secções 2–6, 9, 10, 15, 16 e 18). Regras de produto: `context.md`. Ecrãs de referência: K01, K02 e K03 no canvas https://claude.ai/artifact/A7SP9jQzLiYYApzrY2Y6Sy.

## Restrições globais

- **Custos e verificação:** só recursos gratuitos. Sem CI remoto: a verificação é `npm run verify`, corrida localmente.
- **Supabase remoto:** nenhuma migração vai para o projeto remoto `paia` nesta fase. Nada de `supabase link` nem `db push` sem autorização explícita do responsável.
- **Segredos e dados:** nenhum segredo entra no código nem em commits. O `.env.example` só tem nomes de variáveis. O `seed.sql` só tem dados ilustrativos e só corre localmente.
- **Língua e formatos:** interface em PT-AO, com tratamento por «tu». Datas mostradas em `Africa/Luanda`. Dinheiro em inteiros de Kz.
- **Cores e acessibilidade:**
  - Nunca texto branco sobre `brand` (#FE5B03). Sobre laranja, o texto é sempre `ink` (#022147).
  - Texto com contraste de pelo menos 4,5:1. Alvos de toque de pelo menos 44 px.
  - Anel de foco de 3 px, a 2 px do elemento, em `--focus-ring`.
- **Base de dados:**
  - RLS em todas as tabelas.
  - Funções `SECURITY DEFINER` com `set search_path = ''`, nomes qualificados, verificação de `(select auth.uid())`, e `revoke execute … from public, anon, authenticated` antes de qualquer `grant`.
  - O papel de administrador vem só de `public.admin_users`, através de `private.is_admin()`, nunca do JWT nem dos metadados.
- **Dados académicos:** curso, ano curricular, turno e turma são **texto livre**, sem listas nem marcadores entre parênteses retos.
- **Commits:** cada commit termina com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Pontos a vigiar na revisão

1. **Telefone com espaços, `+244` ou `00244`.** Deve ser normalizado para `9XXXXXXXX` e aceite. `912 34 56` (8 dígitos) deve ser recusado com mensagem junto ao campo. Teste na tarefa 6 (`normalizePhone`) e na tarefa 5 (`check` na base de dados).
2. **Professor ou funcionário que preencheu dados académicos antes de trocar o vínculo.** Esses dados não podem ser gravados. Teste na tarefa 6 (o schema remove-os) e na tarefa 5 (o trigger ignora-os).
3. **Cliente malicioso que chama a API diretamente:**
   - não pode mudar o próprio `affiliation`;
   - não pode inserir-se em `admin_users`;
   - não pode ler o perfil de outra pessoa.
   Teste pgTAP na tarefa 5.
4. **Email já registado ou palavra-passe errada.** A mensagem não pode revelar se a conta existe. Teste na tarefa 6 (`translateAuthError`).
5. **Textos acima do limite enviados sem passar pelo formulário** (nome com 500 caracteres). A base de dados recusa-os. Teste pgTAP na tarefa 5.
